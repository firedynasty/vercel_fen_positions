                How the puzzles are stored (tap to open)

                
Where things live

                
    
                    
  • Supabase is the only source of truth. The category and puzzle dropdowns, Prev / Next, the ?id= links and the puzzle ids all come from the puzzles table. Each puzzle row has a number, shown as #id next to the dropdown.
    • 
                    
  • There is no automatic sync with any file. Nothing you do on this page, and no CSV, can delete puzzles behind your back.
    • 
                


                
💾 Save to Supabase

                
    
                    
  • Saves the FEN in the FEN box. If a PGN is loaded (a puzzle, a pasted PGN, or moves you dropped), it saves the whole PGN instead, variations and comments included.
    • 
                    
  • Adds a new row with a new id at the end of the category. It never replaces a row, so saving the same FEN twice gives two rows.
    • 
                


                
➕ Bulk add

                
    
                    
  • Paste fen,note rows into the textarea; they are added to the chosen category, skipping rows already there.
    • 
                


                
🗑️ Delete (the red button here)

                
    
                    
  • Deletes the puzzle selected in the dropdown from Supabase. It asks you to confirm first and cannot be undone.
    • 
                


                
Access code

                
    
                    
  • Save, bulk add and delete need the server's ACCESS_CODE. The page asks for it the first time and remembers it in this browser (localStorage). A wrong code is forgotten, so you are asked again. Reading puzzles needs no code.
    • 
                


                
Backup and bulk edit: python puzzles_csv.py

                
    
                    
  • --download writes one CSV per category (<category>.csv, columns fen,note, in puzzle order) into ~/Library/CloudStorage/Dropbox/study/chess, a backup you can also edit.
    • 
                    
  • --upload reads those CSVs back into Supabase: rows are matched by FEN (a puzzle keeps its id and ?id= links when you reorder, edit its note or move it to another CSV), new rows are inserted, and Supabase rows that match no CSV row are deleted. It shows the plan and asks first; --dry-run only prints it. It refuses to run if the CSVs hold no puzzles.
    • 
                


                
Links

                
    
                    
  • A ?id= link opens that puzzle. After the puzzle is deleted the link stops working and says "Puzzle not found". Moving it to another category does not break it.
